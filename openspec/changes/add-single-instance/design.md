## Context

Десктопная обёртка (`schadin/harrier-desktop`, Tauri v2) при повторном запуске
создаёт полноценный второй процесс со своим окном и сессией. Показать уже
открытое окно умеет трей: `tray.rs::show_main_window` делает
`unminimize` + `show` + `set_focus` для окна `"main"`.

Перехват повторного запуска полезен (под Niri второе бездекорное окно
«прилипает» поверх основного и его не сфокусировать), но ломает сценарий с
двумя независимыми экземплярами — например, с разными учётными записями. Поэтому
перехват включается настройкой и по умолчанию выключен: поведением по умолчанию
остаётся запуск отдельного экземпляра.

Инвариант протокола не затрагивается. Веб-сборка (Pages) работает без
`src-tauri` и остаётся без изменений.

## Goals / Non-Goals

**Goals:**
- Второй запуск при включённой настройке не создаёт новый процесс/окно, а
  активирует уже работающее.
- При выключенной настройке каждыйый запуск создаёт отдельный экземпляр —
  как до появления перехвата.
- Значение по умолчанию — выключено; переключатель доступен в настройках
  приложения (только десктоп).
- Смена настройки не требует перезапуска уже работающего приложения.
- Поведение активации совпадает с показом из трея (один код, не две реализации).
- Работает на Windows, Linux и macOS.

**Non-Goals:**
- Реализация «сворачивания в трей» и фонового режима — отдельная задача.
- Передача аргументов/файлов из второго запуска в запущенный экземпляр.
- Применение настройки «на лету» к уже запущенным экземплярам: зарегистрировать
  или снять перехват без перезапуска процесса нельзя (плагин подключается на
  этапе сборки приложения).

## Decisions

1. **`tauri-plugin-single-instance`, а не собственный IPC.** Плагин официальный,
   кроссплатформенный и использует нативные механизмы ОС (перехват запуска
   процесса). Альтернативы: реализация сокета/lock-файла вручную — лишний
   код и платформенные нюансы (демон, AppArmor, автозапуск); отказ от второго
   процесса в пользу проверки окна — не работает, второй процесс уже создан.

2. **Колбэк переиспользует `tray.rs::show_main_window`.** Функция станет
   `pub(crate)`; логика показа/фокуса не дублируется. Сейчас она приватная и
   используется из клика по трею и пунктов меню.

3. **Плагин регистрируется первым в цепочке `.plugin(...)`.** Он перехватывает
   запуск до инициализации остальных плагинов и окна; иначе второй процесс
   успеет создать лишние ресурсы.

4. **Зависимость только для десктопных платформ.** Плагин добавляется в
   секцию `[target.'cfg(not(any(target_os = "android", target_os = "ios")))'.dependencies]`
   рядом с `tauri-plugin-global-shortcut`; мобильные платформы сборку не ломает.

5. **Разрешения (capabilities) не меняются.** Плагин работает целиком на
   Rust-стороне и не добавляет JS-команд, поэтому правки
   `capabilities/*.json` и `permissions/desktop-tray.toml` не требуются. Для
   команды записи настройки (`set_single_instance`) действует уже существующая
   политика `core:default` — она покрывает `invoke` с аргументами.

6. **Флаг читает запускаемый процесс, до регистрации плагина.** Решение о том,
   перехватывать ли запуск, принимает второй процесс: он читает файл с флагом и
   либо регистрирует `tauri-plugin-single-instance`, либо работает как самостоятельный
   экземпляр. Поэтому источник истины должен быть доступен до `tauri::Builder` —
   до создания окна и до загрузки фронтенда.

7. **Флаг хранится в файле каталога данных приложения, а не в `localStorage`.**
   Настройки фронтенда лежат в `localStorage` (cinny `settingsAtom`) и читаются
   вебview'ом, которого на момент старта ещё нет; из Rust до создания окна они
   недоступны. Путь к каталогу данных вычисляется вручную — тем же приёмом, что
   уже сделано в `migrate.rs` (`XDG_DATA_HOME` / `HOME`, `Application Support`,
   `APPDATA`) — поэтому новая зависимость (`tauri-plugin-store`, `directories`)
   не нужна. Формат: JSON `{"singleInstance": bool}`, читается с откатом на
   `false` при любой ошибке парсинга или отсутствии файла.

8. **UI и Rust хранят значение в двух местах.** В `settingsAtom` cinny поле
   `singleInstance` нужно для отрисовки переключателя и для сохранения настроек;
   фактический файл в каталоге данных — источник истины для перехвата. Они
   рассинхронизируются только если запись на стороне Rust не удалась — в этом
   случае переключатель в UI возвращается в предыдущее положение, как это уже
   сделано для `autostart` в `ClientNonUIFeatures.tsx`.

9. **Дефолт `false` означает откат к прежнему поведению.** Функция из п.1–4
   включается только по явному решению пользователя; автоматического переноса
   значения из прежних версий не делаем (прежде перехват был безусловным, но
   настройки для его включения ещё не было).

## Risks / Trade-offs

- [Плагин использует локальный сокет/IPC] → Второй экземпляр завершается после
  передачи запуска; в dev-режиме (`tauri dev`) поведение может отличаться —
  проверяется вручную.
- [Второй экземпляр на другой платформе/рантайме может не перехватиться] →
  Критерии приёмки проверяются на текущей платформе разработки (Linux);
  поведение на Windows/macOS определяется плагином.
- [Зависимость добавляется в `Cargo.lock`] → Блокировка отсутствует, обновление
  выполняется при сборке; отдельного обновления lock-файла вручную не требуется.
- [Флаг в файле читается до инициализации Tauri] → Ошибка чтения (нет доступа к
  каталогу, битый JSON) трактуется как «перехват выключен» и логируется в stderr —
  поведение приложения при этом остаётся рабочим, как до появления перехвата.
- [Расхождение значения в `localStorage` и в файле] → Возможно только при сбое
  записи; UI сообщает об ошибке и возвращает переключатель в прежнее положение.
- [Плагин не перехватывает второй процесс, если настройка снята] → Одновременно
  работающих экземпляров может быть несколько; у каждого свой трей (`"main-tray"`)
  — проверяется вручную, при необходимости трей получает идентификатор экземпляра.
