## Context

Десктопная обёртка уже умеет показывать окно из трея и работать в фоне, но автозапуск не реализован: пользователь запускает клиент вручную. Настройки фронтенда уже умеют пробрасываться в Rust через мост `cinny/src/app/utils/desktop.ts` (вызовы `invoke` с гардом `isTauri()`), а секция Desktop в настройках скрыта вне Tauri — схема расширяется без новых подходов.

Инвариант протокола не затрагивается. Веб-сборка (Pages) не имеет доступа к плагину и работает как прежде.

## Goals / Non-Goals

**Goals:**
- Настройка «запускать при входе в систему» в секции Desktop, работающая на Windows, Linux и macOS.
- Состояние настройки в приложении совпадает с состоянием автозапуска в ОС.
- Минимум нового кода: официальный плагин + существующий паттерн синхронизации настроек.

**Non-Goals:**
- Запуск в свёрнутом виде (отдельная задача, `startMinimized` сейчас не используется).
- Задержка автозапуска и параметры командной строки для автозапуска.
- Своя реализация регистрации автозапуска без плагина.

## Decisions

1. **`tauri-plugin-autostart`, а не собственный код.** Плагин официальный,
   закрывает все три платформы (Startup / XDG / LaunchAgent) и предоставляет
   JS-API `enable`/`disable`/`isEnabled`. Альтернативы: ручная запись
   `.desktop`/реестра — платформенные нюансы и расхождения с упакованными
   сборками; пробуждение по таймеру — другой механизм, не системный автозапуск.

2. **Версия плагина 2.5.1.** Начиная с 2.6.0 плагин требует `tauri ^2.12`, а
   в проекте Tauri 2.11.3; обновление фреймворка вынесено в отдельную задачу
   (см. #57). Rust- и JS-версии фиксируются на 2.5.1, чтобы состояние
   совпадало.

3. **Инициализация без аргументов.** `init(MacosLauncher::LaunchAgent, None)`:
   после внедрения одного экземпляра (#36) автозапуск — это обычный старт
   приложения, отдельные аргументы не нужны.

4. **JS-обёртки в `utils/desktop.ts`, состояние — в общих настройках.**
   Настройка `autostart` хранится в `settings.ts` рядом с `showTrayIcon`,
   применяется эффектом в `ClientNonUIFeatures` с тем же debounce (100 мс), что
   и синхронизация трея. Альтернатива: отдельная команда Rust с состоянием в
   `DesktopState` — тогда настройка не пережила бы переустановку/перенос
   конфигурации и расходилась бы с настройками клиента.

5. **Откат настройки при ошибке.** Если `enable()`/`disable()` бросает ошибку,
   значение возвращается к предыдущему (`false`), причина логируется:
   состояние в UI не должно расходиться с ОС.

6. **Проверка патча ребрендинга.** `ClientNonUIFeatures.tsx` входит в
   `0002-rebrand-harrier.patch` — после правки прогоняется
   `npm run rebrand:apply && npm run rebrand:revert`.

## Risks / Trade-offs

- [В dev-режиме автозапуск запишет путь к `target/debug`] → Это ожидаемо и
  относится только к dev-сборке; фиксируется в описании настройки.
- [Ошибка регистрации на отдельной платформе (например, ограничения окружения)]
  → Настройка откатывается, причина логируется, приложение продолжает работу.
- [Плагин требует разрешения `autostart:default`] → Добавляется в
  `capabilities/desktop.json` рядом с `global-shortcut:default`.
