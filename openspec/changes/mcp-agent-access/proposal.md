# Proposal: MCP-доступ к запущенной сессии Harrier

## Why

Пользователю нужен способ автоматизировать свои сценарии в Harrier силами
локального ИИ-агента: прочитать комнаты и таймлайны, отправить сообщение,
поработать с задачами DsTaskBot. Сейчас у агента нет доступа к живой сессии
клиента: Matrix-сессия и ключи E2EE находятся в вебвью, а наружу не выставлено
ни одного управляемого интерфейса.

MCP (Model Context Protocol) — стандартный способ дать агенту инструменты.
Задача: schadin/harrier-project#68.

## What Changes

- **Новая секция настроек «Доступ для агента (MCP)»**: master switch (off по
  умолчанию), порт, bearer-токен (показ/копирование/перегенерация), группы прав,
  подтверждение записи, журнал вызовов.
- **MCP-хост в Rust (Tauri)**: Streamable HTTP только на `127.0.0.1`, проверка
  токена, гейтинг групп прав, динамический `tools/list`
  (`notifications/tools/list_changed`), аудит-лог, таймауты.
- **Мост Rust ↔ вебвью**: request/response поверх Tauri events + commands с
  correlation id; исполнитель тулов в вебвью работает против matrix-js-sdk.
- **Группы тулов**:
  - `read` — `session_info`, `list_rooms`, `get_room`, `read_timeline`,
    `list_room_members`, `get_presence`;
  - `write` — `send_message`, `set_custom_status` (с подтверждением в UI);
  - `e2e` — чтение шифрованных комнат, отдельный тогл, **off по умолчанию**;
  - `dstaskbot` — `dstask_list`, `dstask_all`, `dstask_history`,
    `dstask_list_cached`, `dstask_add`, `dstask_close`, `dstask_file`,
    `dstask_verify`; **регистрируются только при включённом тогле «Доступ через
    MCP» в настройках DsTaskBot** (off по умолчанию). При выключении тулы
    исчезают из `tools/list` и вызовы отклоняются.
- **Подтверждение записи**: перед отправкой сообщения или команды боту вебвью
  показывает диалог с комнатой и текстом (таймаут 60 c → отказ); тогл «не
  спрашивать» для доверенной автоматизации (off по умолчанию).
- **Ошибки без побочных эффектов**: `session_unavailable`, `permission_denied`,
  `room_encrypted`, `confirmation_rejected`, `confirmation_timeout`,
  `bridge_timeout`, `bot_no_response`.
- **Аудит**: кольцевой журнал последних 200 вызовов с просмотром в настройках.
- **Документация**: README (зонтик и `desktop/`), пример конфигурации
  MCP-клиента.

## Capabilities

### New Capabilities

- `agent-access`: MCP-доступ ИИ-агента к запущенной сессии Harrier — настройки и
  токен, локальный транспорт, группы прав и подтверждение записи, каталог
  тулов, динамическая регистрация тулов DsTaskBot, аудит и коды ошибок.

### Modified Capabilities

_(нет — существующие требования не меняются; тогл «Доступ через MCP» в
настройках DsTaskBot описывается как часть `agent-access`, поскольку спецификация
`dstaskbot` ещё не заархивирована в `openspec/specs/`)_

## Impact

- **Репозиторий**: `desktop/` (Rust: новый модуль `mcp`, зависимости
  HTTP-сервера и токена; права Tauri), `desktop/cinny` (форк веб-клиента:
  настройки, исполнитель тулов, диалог подтверждения, i18n).
- **Зонтик**: новая спецификация `openspec/specs/agent-access/spec.md`, README,
  пример конфигурации агента.
- **Протокол Matrix**: инвариант соблюдён — все операции агента выполняются
  существующими механизмами matrix-js-sdk (чтение комнат/таймлайна, отправка
  `m.room.message`, presence, команды боту обычными сообщениями). Новых типов
  событий и обходных путей не вводится.
- **Безопасность**: сеть ограничена loopback; доступ выключен по умолчанию;
  E2EE-чтение и DsTaskBot-тулы — отдельные opt-in; пишущие операции
  подтверждаются; секреты Matrix не покидают вебвью.
- **Риски**: расширение поверхности атаки локального приложения (смягчается
  токеном, loopback, группами прав, подтверждениями, аудитом); зависимость от
  MCP-спецификации, которая развивается (пинуем версию протокола и покрываем
  контрактными тестами).
