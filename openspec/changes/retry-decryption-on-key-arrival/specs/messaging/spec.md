## ADDED Requirements

### Requirement: Повторная расшифровка при появлении ключей
Система SHALL выполнять страховочный повторный проход расшифровки для
нерасшифрованных событий, не попавших в pending-list SDK, при появлении ключей,
чтобы они «оживали» без ручного скролла или перезагрузки. Повторный проход SHALL
запускаться при событиях прихода ключей/бэкапа:
`CryptoEvent.KeyBackupSessionsRemaining` (счётчик достиг 0),
`KeyBackupDecryptionKeyCached`, `DevicesUpdated`, `UserTrustStatusChanged`.

#### Scenario: Появление ключа для события вне pending-list
- **WHEN** ключ сессии появляется (из бэкапа или от устройства), а
  нерасшифрованное событие не попало в pending-list SDK
- **THEN** система повторно вызывает попытку расшифровки для таких событий
- **AND** событие отображается расшифрованным без ручного скролла или перезагрузки

#### Scenario: Событие из кэша расшифровано после восстановления бэкапа
- **WHEN** таймлайн загружен из кэша офлайн, а затем ключ бэкапа становится
  доступным
- **THEN** нерасшифрованные события таймлайна повторно проходят расшифровку

### Requirement: Исключение необратимых причин из ретраев
Система SHALL исключать из повторных попыток расшифровки события с необратимыми
причинами, для которых ключ не может быть получен позже (например,
`MEGOLM_KEY_WITHHELD_FOR_UNVERIFIED_DEVICE`, `SENDER_IDENTITY_PREVIOUSLY_VERIFIED`).

#### Scenario: Невозвратная причина не ретраится
- **WHEN** событие имеет необратимую причину расшифровки
- **THEN** повторная расшифровка для этого события не выполняется

### Requirement: Ненавязчивость повторной расшифровки
Система SHALL выполнять повторную расшифровку без блокировки интерфейса и с
дедупликацией вызовов (debounce), чтобы не запускать гонку ретраев при
массовом приходе ключей.

#### Scenario: Массовый приход ключей
- **WHEN** приходит несколько событий появления ключей подряд
- **THEN** повторный проход расшифровки выполняется один раз за короткий
  интервал времени
- **AND** интерфейс остаётся отзывчивым во время повторной расшифровки
