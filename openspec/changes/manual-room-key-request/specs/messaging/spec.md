## ADDED Requirements

### Requirement: Ручной запрос ключа сессии
Система SHALL предоставлять пользователю возможность вручную запросить
недостающий ключ сессии у устройств отправителя для нерасшифрованного сообщения
путём отправки to-device события `m.room_key_request`. Запрос SHALL быть доступен
только для ретраябельных причин расшифровки (`MEGOLM_UNKNOWN_INBOUND_SESSION_ID`,
`HISTORICAL_MESSAGE_WORKING_BACKUP`), когда ключ может быть получен позже.

#### Scenario: Запрос ключа для нерасшифрованного сообщения
- **WHEN** сообщение не расшифровано с ретраябельной причиной
  (`MEGOLM_UNKNOWN_INBOUND_SESSION_ID` или `HISTORICAL_MESSAGE_WORKING_BACKUP`)
- **THEN** на сообщении отображается действие «Запросить ключ»
- **AND** при активации действия отправляется `m.room_key_request` устройствам
  отправителя с `request_id`, `room_id`, `sender_key` и `session_id` из
  `event.getWireContent()`

#### Scenario: Запрос ключа недоступен для необратимой причины
- **WHEN** событие не расшифровано с причиной, для которой ключ не может быть
  получен позже (например, `MEGOLM_KEY_WITHHELD_FOR_UNVERIFIED_DEVICE`)
- **THEN** действие «Запросить ключ» SHALL отсутствовать

#### Scenario: Ключ получен после запроса
- **WHEN** после отправки `m.room_key_request` отправитель отвечает forwarded
  ключом и SDK импортирует его
- **THEN** SDK автоматически ретраит расшифровку ожидающего события
- **AND** сообщение расшифровывается и отображается обычным образом

### Requirement: Ограничение частоты запросов ключа
Система SHALL ограничивать частоту ручных запросов ключа, чтобы исключить «шторм
запросов» (`request storm`). Повторная отправка запроса для одной и той же
`session_id` SHALL быть дедуплицирована по `request_id`.

#### Scenario: Повторный клик по «Запросить ключ»
- **WHEN** пользователь повторно активирует «Запросить ключ» для одного и того же
  нерасшифрованного события в течение короткого интервала времени
- **THEN** повторный `m.room_key_request` не отправляется
- **AND** действие остаётся в состоянии «запрос отправлен»
