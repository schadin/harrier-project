## Why

Когда сообщение в E2EE-комнате не расшифровывается, клиент показывает единый
заглушечный текст «Unable to decrypt message» (`FallbackContent.tsx`), не объясняя
причину. При этом matrix-js-sdk v41.7.0 (Rust crypto) для каждого неудачно
расшифрованного события выставляет `decryptionFailureReason` (`DecryptionFailureCode`),
что позволяет отличить временные случаи (ключ ещё не получен) от случаев,
требующих действия пользователя (неверифицированное устройство, отсутствие/
недоступность бэкапа, потеря доверия к отправителю). Этот код сейчас
игнорируется — UX тупиковый.

## What Changes

- Вместо единого плейсхолдера отображать конкретную причину неудачной расшифровки.
- Маппинг значений `DecryptionFailureCode` в локализованные понятные сообщения.
- Контекстное действие (CTA) по причине: «Запросить ключ» (см. #28),
  «Верифицировать устройство», «Настроить/восстановить бэкап ключей».
- Только используемые существующие данные протокола Matrix / SDK — без
  нестандартных обходных путей.

## Capabilities

### New Capabilities

_Нет новых доменов._

### Modified Capabilities

- `messaging`: добавляется требование о представлении нерасшифрованных сообщений —
  показ причины (`decryptionFailureReason`) и контекстного действия вместо
  единой заглушки.

## Impact

- **Код (форк `schadin/harrier`):**
  - `src/app/components/RenderMessageContent.tsx` — ветка `m.bad.encrypted`;
  - `src/app/components/message/content/FallbackContent.tsx` — компонент-заглушка;
  - компонент контента сообщения и прокидывание `mEvent` в рендер;
  - файлы локалей (`ru`, `en`, `de`).
- **Зависимости:** `decryptionFailureReason` / `DecryptionFailureCode` из
  matrix-js-sdk ≥ 41.7.0 (уже используется).
