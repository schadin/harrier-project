## Context

В E2EE-комнатах сообщение, которое не удалось расшифровать, рендерится
`MessageBadEncryptedContent` — единой заглушкой «Unable to decrypt message»
(`FallbackContent.tsx:34`, ветка `m.bad.encrypted` в `RenderMessageContent.tsx:263`).

matrix-js-sdk v41.7.0 (Rust crypto) уже предоставляет структурированную причину:
`MatrixEvent.decryptionFailureReason` — код из `DecryptionFailureCode`
(`MEGOLM_UNKNOWN_INBOUND_SESSION_ID`, `MEGOLM_KEY_WITHHELD_*`,
`HISTORICAL_MESSAGE_*`, `SENDER_IDENTITY_*` и др.). SDK также кладёт в клир-контент события человекочитаемую строку `body`
(«** Unable to decrypt: … **`), но она не стабильна и не локализуема.

Смежные изменения (отдельные задачи): ручной запрос ключа (#28), персист SSSS и
авто-восстановление бэкапа (#29), страховочный rescan (#30). Данное изменение
только представляет причину пользователю и прокладывает CTA к существующим
экранам/потокам.

## Goals / Non-Goals

**Goals:**
- Локализованный текст причины по `decryptionFailureReason`.
- Контекстное действие (CTA) для причин, где оно эффективно (запросить ключ,
  верифицировать устройство, настроить/восстановить бэкап).
- Чистая отделимая от рендера логика маппинга (тестируемые функции).

**Non-Goals:**
- Реализация самого запроса ключа (#28) — здесь только точка вызова CTA.
- Реализация восстановления/настройки бэкапа (#29) — только навигация к панели.
- Страховочный rescan (#30).
- Изменение протокола Matrix или добавление новых событий.

## Decisions

**1. Источник данных — `decryptionFailureReason`, а не `body`.**
Используем структурированный enum `DecryptionFailureCode` из
`mEvent.decryptionFailureReason`. Альтернатива — парсинг строки `body`
(«** Unable to decrypt: … **») отвергнута: строка нестабильна, не локализуема и
уже продублирована enum-ом.

**2. Маппинг — чистая функция, язык вне маппинга.**
Функция `getDecryptionFailureReason(code)` возвращает устойчивый ключ
`{ titleKey, actionKey? }`, не текст. Локализация — на уровне рендера через
i18next. Альтернатива «строки прямо в маппинге» отвергнута: раздувает функцию и
мешает i18n.

**3. Прокидывание через props, а не чтение события в листе.**
`decryptionFailureReason` (и при необходимости `getWireContent()` для CTA)
передаётся в контент сообщения через props, начиная от `Message.tsx`. Лист
остаётся чистым. Альтернатива «читать `mEvent` прямо в компоненте-заглушке»
отвергнута: сложнее тестировать и переиспользовать.

**4. CTA — внешний колбэк, навигация на существующие экраны.**
CTA реализуется как опциональный колбэк из контекста сообщения:
- запрос ключа → колбэк, который будет реализован в #28;
- верифицировать устройство → навигация в настройки устройств
  (`DeviceVerificationSetup` / список устройств);
- бэкап → открытие `BackupRestore` панели.
Для причин без эффективного действия CTA отсутствует.

**5. Фолбэк для неопределённости.**
`null` / `UNKNOWN_ERROR` → текущий общий текст. Это сохраняет деграду на случай
изменений SDK.

## Risks / Trade-offs

- **Отсутствие причины** (расшифровка не предпринималась) → показываем общий
  текст; событие будет обработано rescan-ом (#30).
- **CTA «Запросить ключ» без реализации (#28)** → до завершения #28 CTA скрывать
  или показывать в disabled-состоянии; не оставлять «мёртвую» кнопку.
- **Имена новых i18n-ключей** → завести ключи в `ru`/`en`/`de` с фолбэком на
  английский; при нехватке перевода — общий текст.
- **Новые коды `DecryptionFailureCode` в будущих версиях SDK** → маппинг построен
  на `switch` с дефолтом на общий текст; новые коды безопасно деградируют.

## Migration Plan

Изменение только во фронтенде форка `schadin/harrier` (подмодуль `cinny/`).
Миграции данных нет. Откат — revert коммита. Развёртывание — обычным релизным
циклом (dev HMR / release-сборка).
