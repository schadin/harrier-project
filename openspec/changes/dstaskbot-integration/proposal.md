# Proposal: Интеграция DsTaskBot

## Why

DsTaskBot (`@dstaskbot:ds-core.ru`) — Matrix-бот управления задачами, который
общается обычными сообщениями `m.room.message`: текстовые команды, текстовые
ответы со списками задач. Сегодня работа с ним требует ручного ввода команд и
чтения «сырого» текста, а служебные сообщения засоряют таймлайн. Harrier может
дать нативный UX поверх этого протокола без единого изменения на стороне бота
и без выхода за рамки протокола Matrix (ответы бота надёжно коррелируются с
командами через `m.in_reply_to`).

Задача: schadin/harrier-project#50.

## What Changes

- Новая группа настроек **«DsTaskBot»**: MXID бота (предзаполнено
  `@dstaskbot:ds-core.ru`), отдельные переключатели функций. По умолчанию всё
  выключено (opt-in).
- **Помощники отправки команд**: slash-шорткаты
  (`/dstask help|list|all|history|close N|file N|verify`, в личке — `add`),
  автодополнение номеров задач для `close` из последнего распознанного списка.
- **Режим лички с ботом**: команды без упоминания (`!list`, `!add текст`,
  `!add @user текст`) — определяется по составу участников / `m.direct`;
  в обычной комнате команда отправляется после упоминания бота
  (`@bot !list`, `@bot @user текст`).
- **Парсер ответов бота** (изолированный модуль): распознавание списков задач
  (паттерн `📌 /N текст (@mxid)`), подтверждений создания и закрытия;
  детерминированное ожидание ответов (`list` — 2 сообщения, `all`/создание/
  закрытие — 1) с таймаутом; graceful fallback на обычный текст.
- **Карточки задач** в таймлайне вместо сырого текста ответов бота:
  номер и название одной строкой (номер — обычным текстом, без `/`),
  исполнитель, кнопки «Закрыть» (`!close N`) и «Файлы» (`!file N`);
  компактные карточки «Задача создана», «Задача закрыта» и карточки-уведомления
  для коротких служебных ответов бота.
- **Вкладка «Задачи»** в комнате: секции «Назначены мне» / «Назначены мной»,
  автообновление после создания/закрытия задачи через UI клиента.
- **Сворачивание служебных сообщений** в таймлайне обычных комнат: команды
  (`!help`, `!list`, `!all`, `!history`, `!close N`, `!file N`, `!verify`,
  упоминание бота с командой) и короткие служебные ответы бота (подтверждения
  и заглушки без списка задач). Ответы со списками задач остаются карточками;
  сворачивание применяется и в личке с ботом.
- **Дополнительные команды**: `!history` (история закрытых задач),
  `!file N` (вложения задачи), `!verify` (запрос проверки устройства бота),
  `!add` (личная задача в личке). Теги (`#тег`), сроки и напоминания клиент
  пробрасывает как обычный текст без специального разбора.
- **Внешняя зависимость** (не блокирует реализацию): запрос разработчику бота
  на добавление структурированного ключа `com.dstask` в `content` ответов
  (JSON с типом ответа, массивами задач и ID созданной задачи). При появлении
  парсер переключается на JSON.

## Capabilities

### New Capabilities

- `dstaskbot`: интеграция с ботом задач DsTaskBot — настройки, помощники
  команд, распознавание и рендер ответов, вкладка «Задачи», сворачивание
  служебных команд.

### Modified Capabilities

_(нет — существующие требования не меняются)_

## Impact

- **Репозиторий**: форк веб-клиента (`desktop/cinny`, подмодуль) — композер
  (шорткаты, автодополнение), рендер таймлайна (карточки, сворачивание),
  навигация комнаты (вкладка «Задачи»), настройки.
- **Зонтик**: `openspec/specs/dstaskbot/spec.md` (новая спецификация), i18n.
- **Протокол**: только стандартные `m.room.message` и `m.in_reply_to`;
  инвариант протокола соблюдён, обходных путей нет.
- **Внешние зависимости**: разработчик DsTaskBot (структурированный ключ
  `com.dstask`) — опционально, не блокирует.
- **Риски**: текстовый формат ответов бота может измениться — смягчается
  изоляцией парсера, тестами на реальных событиях и graceful fallback.
