# Design: Интеграция DsTaskBot

## Context

DsTaskBot — внешний Matrix-бот (разработчик доступен, изменения на его стороне —
отдельный процесс). Протокол разобран по реальным событиям
(issue schadin/harrier-project#50) и по документу формата конверта, присланному
разработчиком бота.

- Транспорт: `m.room.message` (`m.text`; вложения — msgtype `m.file`), ответы
  бота — `m.in_reply_to` на событие-команду, `m.mentions` заполнено,
  E2E-прозрачно. `MatrixEvent.getType()` у расшифрованного события возвращает
  очищенный тип (`m.room.message`), поэтому конверт доступен в обычном
  обработчике сообщений; отдельная ветка для encrypted не требуется.
- Конверт `ru.ds_core.bot`: `{ v: 1, kind, task?, tasks?, files?, user?, ok? }`
  в `content` сообщений бота. Классификация — по `kind`, не по тексту `body`.
  Отсутствие конверта допустимо (старые сообщения).
- Команды: в комнате — сначала упоминание бота, затем команда (`@bot !list`,
  `@bot @user текст`), в личке — без упоминания (`!list`, `!add текст`,
  `!add @user текст`). Все команды с префиксом `!`: `!help`, `!list`, `!all`,
  `!history`, `!close N`, `!file N`, `!verify`; в личке дополнительно `!add`.
  Устаревший синтаксис без `!` и закрытие по `/N` ботом не поддерживаются.
- `kind`: `help`, `created`, `closed`, `already_closed`, `list`, `history`,
  `report`, `reminder`, `file`, `file_attached`, `verify_request`,
  `verify_started`, `verify_pending`, `verify_approved`, `verify_denied`,
  `undecryptable`, `error`.
- Поля задачи: `id`, `title`, `author`, `assignee?`, `status` (`open|closed`),
  `chat_id?`, `chat_title?`, `created_at?`, `due_at?`, `remind_at?`,
  `closed_at?`, `tags?`. Время — RFC3339 UTC.
- Вложения: `files[]` с `name`, `mime_type?`, `size?`.

Реализация — в форке веб-клиента (`desktop/cinny`), React 18 + TS +
matrix-js-sdk + jotai. Инвариант проекта: только механизмы протокола Matrix.

## Goals / Non-Goals

**Goals:**
- Opt-in интеграция: настройки, помощники команд, карточки, сворачивание
  служебных команд.
- Классификация сообщений бота по конверту `ru.ds_core.bot` с graceful
  fallback на текстовый разбор для старых сообщений.

**Non-Goals:**
- Доработка бота — внешняя зависимость.
- Вкладка «Задачи» — удаляется в этой итерации как неудобная, проработка
  вынесена на отдельную задачу.
- Интерактивность средствами вне протокола (кнопки в событиях и т.п.).
- Поддержка нескольких разных ботов одновременно (один MXID в настройках).

## Decisions

### 1. Изолированный модуль конверта + текстовый fallback
Разбор вынесен в чистые модули: `envelope.ts` (валидация и нормализация
`ru.ds_core.bot` — версия `v === 1`, известный `kind`, поля задачи/списка/
файлов) и `parser.ts` (классификация события). `parseBotMessage` сначала
пробует конверт (если отправитель — бот и поле присутствует), иначе —
существующий текстовый разбор. Неизвестный `kind`, чужой `v` или ошибка
структуры → graceful fallback (обычный текст). Тесты — на реальных событиях и
на всех kinds.

_Почему:_ формат может меняться; изоляция и fallback ограничивают blast radius.

### 2. Соответствие `kind` → UI
| kind | Рендер |
|------|--------|
| `help` | обычный текст (длинная справка, не карточка) |
| `created` | карточка «Задача создана» |
| `closed` | карточка «Задача закрыта» |
| `already_closed` | компактное уведомление (info) |
| `list` / `report` | карточка списка задач, секции «Назначены мне» / «Назначены мной» |
| `history` | карточка закрытых задач; кнопка «Закрыть» скрыта |
| `reminder` | компактная карточка-напоминание с задачей |
| `file` | штатный файл-бабл Cinny + компактная карточка задачи с именами файлов |
| `file_attached` | компактная карточка с именами файлов |
| `verify_request`/`started`/`pending`/`approved` | компактное уведомление (info) |
| `verify_denied` | компактное уведомление (error) |
| `error` | компактное уведомление (error), без кнопок (действие всё равно не пройдёт) |
| `undecryptable` | компактное уведомление |

### 3. Поля задачи в карточках
Номер и название одной строкой (номер — обычный текст, без `/`), исполнитель,
статус. При наличии — срок/напоминание в локальном времени (утилиты
форматирования дат клиента) и теги как `#тег`. `chat_title` показывается только
для личных списков (`scope: personal`) — там задача может быть из другой
комнаты.

### 4. Кнопки — чисто клиентский рендер, действия — обычными сообщениями
«Закрыть» отправляет `!close N`, «Файлы» — `!file N`, как обычные сообщения
`m.room.message` (в комнате — с упоминанием бота, в личке — без). Номер задачи
рендерится обычным текстом без `/` и без кнопки. Для `history` кнопка «Закрыть»
не показывается. Никаких кастомных типов событий — инвариант протокола.

### 5. Классификация по assignee, не по заголовкам
Секции «Назначены мне» / «Назначены мной» определяются сравнением `assignee`
с MXID текущего пользователя (из конверта; в текстовом fallback — MXID из
`(@mxid)`). Пустые списки (`items: []`) отображаются как пустые.

### 6. Сворачивание служебных сообщений
Сворачиваются команды боту и короткие служебные ответы. При наличии конверта
ответ сворачивается для kinds `created`, `closed`, `already_closed`,
`reminder`, `error`, `verify_*`, `undecryptable`; не сворачиваются списки
(`list`/`history`/`report`), вложения (`file`/`file_attached`) и справка
(`help`). Без конверта — прежний предикат: ответ бота без строк задач и не
более двух непустых строк. Свёрнутый ответ раскрывается по клику. Управляется
тем же тумблером «Сворачивать команды», применяется и в личке с ботом.

### 7. Настройки — отдельная группа, jotai + localStorage
Следуем существующим паттернам настроек клиента. Ключи: `dstaskbot.enabled*`,
`dstaskbot.botMxid` (дефолт `@dstaskbot:ds-core.ru`). Всё off по умолчанию.
Переключатели: помощники команд, карточки, сворачивание команд (тумблер
вкладки удалён вместе с вкладкой). Элементы управления (поле MXID,
переключатели) размещаются на отдельной строке под заголовком/описанием, а не в
одной строке с ними (компонент `SettingTile` с контролом в `children`).

### 8. Синтаксис команд — единая сборка с учётом режима
Все команды формируются одной функцией: префикс `!` для любой команды,
упоминание бота добавляется только в обычной комнате. Создание задачи: в
комнате — `@bot @исполнитель текст`, в личке — `!add текст` /
`!add @исполнитель текст`. Теги, сроки и текст напоминаний клиент не
разбирает — пробрасывает как есть. `!help`, `!history`, `!file N`, `!verify`
и `!add` доступны через шорткат `/dstask`; `!file N` дополнительно — кнопкой
на карточке задачи.

### 9. Удаление вкладки «Задачи»
Вкладка, настройка `tasksTabEnabled`, компонент `TasksTab`, хук ожидания
списка и связанные атомы удаляются. Автодополнение номеров для `close`
сохраняется: оно опирается на последний распознанный в таймлане список
(`list`/`history`/`report`), а не на вкладку. Проработка нового способа
просмотра задач — отдельная задача.

### 10. Сохранность конверта
Клиент не редактирует сообщения бота; ответы и пересылка создают новые события,
конверт не переписывается. Отсутствие конверта трактуется как норма (старые
сообщения), а не как ошибка.

## Risks / Trade-offs

- [Конверт отсутствует в старых сообщениях] → текстовый fallback, покрытый
  тестами; отсутствие поля не считается ошибкой.
- [Бот меняет `kind` или версию `v`] → неизвестный `kind`/чужой `v` дают
  graceful fallback на обычный текст; версия проверяется явно.
- [Сворачивание скроет осмысленные сообщения] → сворачиваются только команды
  по полному синтаксису и короткие служебные kinds; списки задач, вложения и
  справка не сворачиваются; настройка отключаема.
- [Удаление вкладки «Задачи»] → функциональность просмотра задач временно
  отсутствует в UI; автодополнение `close` сохранено, новая проработка —
  отдельная задача.

## Migration Plan

Не требуется: новая opt-in функциональность, значения настроек по умолчанию
выключены. Тумблер вкладки «Задачи» удаляется; у ранее включивших его
пользователей настройка просто игнорируется, поведение клиента — без вкладки.

## Open Questions

- Формат ответа `!history` в текстовом fallback (при наличии конверта
  классификация по `kind: history`).
- Возможность клиентских действий для `verify_request` (команды `!approve`;
  команда отклонения в документе не описана) — сейчас только информационные
  уведомления.
- Способ просмотра задач взамен удалённой вкладки.
