# Design: реорганизация репозиториев (фаза −1 эпика #59)

## Context

Сегодня клиент (форк Cinny) подключён к `harrier-desktop` как git-подмодуль
`cinny/`, а брендинг накатывается патчем `0002-rebrand-harrier.patch` на время
сборки и откатывается после — ради сохранения подмодуля в upstream-состоянии.
Pages-деплой веб-версии (`schadin/harrier`) клонирует `harrier-desktop` ради
скрипта ребрендинга и ассетов. В рамках эпика
[#59](https://github.com/schadin/harrier-project/issues/59) принято:
синк с upstream прекращается, веб становится legacy и остаётся в
`schadin/harrier` (Pages-URL `schadin.github.io/harrier/` привязан к имени
репозитория и должен сохраниться), десктоп развивается как монорепо
(UI + `src-tauri` + будущий crate `harrier-core`).

Ограничения: `VITE_BASE=/harrier/` и URL Pages зависят от имени репозитория
`harrier`; переименование/перенос веб-репо убьёт существующие ссылки (редиректов
Pages для переименованных репозиториев нет). Rust-код `src-tauri` не
затрагивается.

## Goals / Non-Goals

**Goals:**
- Клиент входит в дерево `harrier-desktop` с сохранением git-истории.
- Брендинг закоммичен постоянно в обоих репозиториях; rebrand-механика удалена.
- `schadin/harrier` деплоится на Pages автономно, без клонирования desktop.
- Релизный цикл desktop — в одном репозитории; процесс и документация обновлены.
- Работоспособность релизов и dev-режима не сломана ни на одном шаге.

**Non-Goals:**
- Любые изменения кода клиента, кроме брендинга и сборочной обвязки.
- Rust-ядро и контракт `@harrier/core` (фазы 0+ эпика).
- Перенос/переименование веб-репозитория, смена Pages-URL.
- Удаление netlify/PR-preview workflows веб-legacy (остаются как есть).

## Decisions

### D1. Клиент переезжает в `harrier-desktop` через subtree merge
`git subtree add` (или `git read-tree`-эквивалент) ветки `harrier` репозитория
`schadin/harrier` в `desktop/client/` с полной историей. Альтернативы:
простое копирование файлов (теряется история — отвергнуто), оставить подмодуль
(сохраняет двойные релизы и двойные теги — отвергнуто, т.к. синк с upstream
отменён). Путь `client/` (а не `cinny/`): имя отражает роль, а не происхождение;
каталог `cinny/` упраздняется. Ссылка на исходный репозиторий фиксируется в
коммите слияния.

### D2. Брендинг коммитится навсегда в обоих репозиториях
Патч применяется один раз к коду клиента; ассеты (`assets/harrier*.svg`,
favicon-наборы, apple/android) переносятся в дерево. `scripts/rebrand.mjs`,
`0002-rebrand-harrier.patch`, шаги rebrand в `beforeBuildCommand`/
`beforeDevCommand` (`tauri.conf.json`) и npm-скрипты `rebrand:*` удаляются.
Альтернатива (перенести rebrand-механику в веб-репо) отвергнута: она
существовала только ради upstream-синка. Для веб-legacy брендинг коммитится в
ветку `harrier` репозитория `schadin/harrier` — тот же набор изменений.

### D3. `pages-deploy.yml` очищается от зависимости от desktop
Шаги клонирования `harrier-desktop` и запуска `rebrand.mjs` удаляются; workflow
сводится к «npm ci → build → deploy-pages». `VITE_BASE=/harrier/`,
`VITE_VERSION`, `.nojekyll`, concurrency group `pages` — без изменений.

### D4. Единый `config.json` в монорепо
Сейчас `desktop/config.json` копируется поверх `cinny/config.json` при старте.
После переезда остаётся один `client/config.json`; шаг копирования из
`package.json` desktop удаляется. Содержимое двух файлов сейчас идентично —
конфликтов слияния нет.

### D5. Версионирование без подмодуля
`scripts/update-version.mjs` упрощается: удаляется логика фетча тегов и
переключения подмодуля cinny; bump продолжает синхронизировать `package.json`,
`Cargo.toml`/`Cargo.lock`, `tauri.conf.json` и вывод `wix.version`. Версии
веб-legacy больше не синхронизируются с десктопом.

### D6. Документация и зонтик обновляются тем же change
`docs/RELEASING.md` (релиз в одном репозитории), `AGENTS.md` зонтика и desktop
(состав репозиториев, команды разработки), `openspec/config.yaml`
(репозиторная карта, описание архитектурных особенностей: удаление пункта про
ребрендинг при сборке). При архивации change дополнительно обновляются
`Purpose`/`Terms` главной спецификации `appearance`, которые OpenSpec delta не
изменяет автоматически.

## Risks / Trade-offs

- [Потеря истории файлов клиента при неверном слиянии] → subtree merge с
  проверкой `git log --follow` на нескольких файлах до удаления подмодуля.
- [Pages-деплой сломается после коммита брендинга (двойное применение патча
  в старом workflow)] → коммит брендинга и правка `pages-deploy.yml` идут
  одним релизом веб-legacy; после мержа — контрольный релиз/деплой.
- [Расхождение кода клиента между монорепо и веб-legacy с первого же дня] →
  принято осознанно: веб-legacy заморожен, получает только критические фиксы
  (cherry-pick при необходимости).
- [Ссылки на пути `cinny/...` в скриптах, CI, документации] → полный поиск по
  строке `cinny` в desktop и зонтике; гейты `lint`/`typecheck` и сборка PR
  как проверка.
- [Локальные репозитории разработчиков с инициализированным подмодулем] →
  инструкция по переинициализации в README/RELEASING (`git submodule deinit`,
  чистый клон).

## Migration Plan

Порядок (каждый шаг — отдельный коммит, приложение работает после каждого):

1. `schadin/harrier`: коммит брендинга + ассетов, очистка `pages-deploy.yml`,
   проверка Pages-деплоя (тег патч-релиза веб-legacy).
2. `harrier-desktop`: subtree merge клиента в `client/`, применение брендинга,
   перенос ассетов, обновление путей (`tauri.conf.json`, `package.json`,
   workflows), удаление подмодуля и rebrand-механики, упрощение
   `update-version.mjs`.
3. Зонтик: обновление `docs/RELEASING.md`, `AGENTS.md`, `openspec/config.yaml`.
4. Контроль: PR-сборка (`test.yml`), `npm run tauri dev`, `npm run tauri build`,
   релизный цикл на следующем предрелизе.

Rollback: до публикации — откат коммитов; подмодульная схема восстанавливается
из истории git без потерь (ничего не пушится без явной команды).

## Open Questions

- Имя каталога клиента в монорепо: `client/` (предложено) — финально
  утверждается при реализации.
- Точная форма слияния с историей (`git subtree add` vs ручной `read-tree`) —
  выбирается при реализации по результату пробного прогона.
