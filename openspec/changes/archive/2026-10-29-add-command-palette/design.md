# Design: add-command-palette

**Задача:** [schadin/harrier-project#58](https://github.com/schadin/harrier-project/issues/58)

## Context

В кодовой базе Harrier (форк Cinny, `desktop/cinny`) уже существует глобальная
модалка поиска `src/app/features/search/Search.tsx`:

- открывается по **Ctrl/Cmd+P** (`isKeyHotkey('mod+k')` в `SearchModalRenderer`,
  подключён в `src/app/pages/Router.tsx`), состояние — jotai-атом
  `src/app/state/searchModal.ts`;
- ищет комнаты/DM/спейсы с префиксами `#`, `@`, `*`;
- клавиатурная навигация через `useListFocusIndex`, подсветка совпадений через
  `highlightText`/`makeHighlightRegex`, FocusTrap, `useAsyncSearch`.

То есть каркас палитры (шорткат, модалка, фокус-ловушка, асинхронный поиск)
уже есть; чего нет — командного слоя (действия, настройки, пользователи,
создание комнат) и fuzzy-матчинга (текущий `AsyncSearch.ts` работает по
`startsWith`/`contains`).

Все нужные действия уже существуют как переиспользуемые API:

| Действие | Существующий API |
|----------|------------------|
| Переход к комнате/спейсу | `useRoomNavigate()` → `navigateRoom`, `navigateSpace` |
| Открытие раздела настроек | `useOpenSettingsPage()` + enum `SettingsPages` (`src/app/state/settingsNav.ts`) |
| Смена статуса | `setCustomStatus`/`setCustomStatusWithTime` + `DEFAULT_STATUS_PRESETS` + настройка `statusPresets` (`src/app/plugins/custom-status.ts`) |
| Mute комнаты | `useSetRoomNotificationPreference(roomId)` / `setRoomNotificationPreference` |
| Mark as read | `markAsRead(mx, roomId, privateReceipt)` (`src/app/utils/notifications.ts`); «прочитать всё» — цикл по комнатам (референс: `Home.tsx`, `Space.tsx`) |
| Logout | `logoutClient(mx)` (`src/client/initMatrix.ts`) + `LogoutDialog` |
| Создание комнаты | `useOpenCreateRoomModal(spaceId?, type?)` (`src/app/state/createRoomModal.ts`) |
| Создание DM | `CreateChat` / роут `/direct/create/` (`src/app/pages/client/direct/DirectCreate.tsx`) |

Ограничения: инвариант протокола (только механизмы Matrix через matrix-js-sdk);
изменения только в веб-клиенте, десктоп-обёртка (Rust/Tauri) не затрагивается.

## Goals / Non-Goals

**Goals:**

- Единая точка входа для навигации и действий: Ctrl/Cmd+P из любого экрана.
- Поиск по комнатам (название, алиас, ID), пользователям (имя, MXID),
  пространствам и разделам настроек.
- Команды: смена статуса (пресеты), mute текущей комнаты, mark all as read,
  logout, создание комнаты/DM/пространства.
- Fuzzy-поиск с подсветкой совпадений, группировка результатов по категориям,
  история последних действий, полное управление с клавиатуры.

**Non-Goals:**

- Глобальный хоткей на уровне ОС (Tauri global-shortcut) — явно исключён.
- Расширяемый реестр команд для сторонних плагинов — закладываем архитектуру
  (реестр как структура данных), но публичный plugin API не делаем.
- Настраиваемые пользовательские шорткаты — не в этом изменении.
- Поиск по сообщениям (существует отдельно в `features/message-search`).

## Decisions

### D1. Развить существующую Search-модалку, а не строить параллельную палитру

`Search.tsx` уже владеет шорткатом `mod+k` и решает половину задачи. Создание
второй модалки на тот же шорткат дало бы конфликт и дублирование. Вместо этого
модалка эволюционирует в палитру: к источнику «комнаты/DM/спейсы» добавляются
источники «пользователи», «настройки», «действия».

**Альтернатива:** отдельный компонент `CommandPalette.tsx` с нуля — отклонена:
дублирование логики фокуса, навигации и асинхронного поиска, риск расхождения
поведения.

### D2. Реестр источников и команд как данные

Палитра строится вокруг списка провайдеров элементов:

```ts
type PaletteItem = {
  id: string;
  category: 'rooms' | 'people' | 'spaces' | 'settings' | 'actions';
  title: string;        // отображаемое имя (комната, MXID, название команды)
  keywords: string[];   // дополнительные ключи поиска (алиас, roomId, имя раздела)
  icon?: ...;
  run: () => void | Promise<void>;  // синхронный переход или async-действие
};
```

Каждый провайдер (комнаты, люди, настройки, действия) возвращает массив
`PaletteItem`; общий конвейер нормализует, fuzzy-матчит, сортирует и группирует
по `category`. Это даёт задел для будущих команд/плагинов без публичного API.

**Альтернатива:** захардкоженные ветки `if/else` по типу результата — отклонена:
не масштабируется на новые категории.

### D3. Fuzzy-поиск — расширение собственного матчера, без новой зависимости

Текущий `AsyncSearch.ts` (`normalize`, `matchQuery`: startsWith/contains)
расширяется subsequence-матчером (символы запроса идут в порядке, но не
обязательно подряд) с ранжированием: точное > префикс > подстрока >
subsequence. Подсветка — существующий `highlightText`/`makeHighlightRegex`,
для subsequence — подсветка по индексам совпавших символов.

**Альтернатива:** добавить `fuse.js` (~7 КБ gzip) — отклонена: ради одного
матчера зависимость не нужна, а собственный subsequence-алгоритм (~50 строк)
покрывает сценарии палитры и сохраняет единый пайплайн `useAsyncSearch`.

### D4. Пользователи — из известных комнат, без серверного user directory

Список людей собирается из членов известных комнат (matrix-js-sdk
`Room.getMembers()`, в первую очередь DM) — это локальные данные синка.
Выбор пользователя: если есть DM-комната (`getDMRoomFor`) — переход в неё,
иначе — открытие `CreateChat` с `defaultUserId`. Серверный `/user_directory/search`
не используем в базовой версии (шумные результаты, сеть на каждый ввод);
можно добавить позже как отдельный провайдер.

### D5. Настройки — статический реестр разделов

Разделы настроек — фиксированный список из enum `SettingsPages` (General,
Account, Status, Notifications, Devices, Emojis & Stickers, Developer Tools,
About) с локализованными названиями и keywords. Выбор — `useOpenSettingsPage()`.
Динамического сканирования не требуется.

### D6. Действия — переиспользование существующих API, async с индикатором

Команды вызывают существующие функции (таблица выше). Асинхронные действия
(mark all as read, logout, смена статуса) показывают индикатор выполнения
(spinner в строке команды / состояние модалки) и закрывают палитру по
завершении; ошибки — существующими механизмами уведомлений клиента.
Mark all as read учитывает настройку `hideActivity` (private receipts) —
как существующие реализации в `Home.tsx`/`Space.tsx`.

### D7. История последних действий — localStorage

Последние N (10) выполненных элементов палитры сохраняются в localStorage
(ключ вида `harrier_palette_recent`) как список `id`. При пустом запросе
палитра показывает историю (если есть) поверх подсказок пустого состояния.
Элементы истории, ставшие невалидными (удалённая комната), молча
отфильтровываются при рендере.

### D8. Шорткаты, независимые от раскладки клавиатуры

Текущий обработчик `isKeyHotkey('mod+k')` матчится по `event.key`, значение
которого зависит от раскладки: в русской раскладке физическая клавиша K даёт
`л`, и шорткат не срабатывает. Матчинг шортката палитры (и всех её
буквенных/символьных шорткатов, включая префиксы `#`/`@`/`*`) переводится на
`event.code` (`KeyP` и т.п.) — физическую клавишу, не зависящую от раскладки
и языка ввода. Проверка модификаторов (`mod` = Ctrl/Cmd) сохраняется.
Это же правило применяется ко всем будущим глобальным шорткатам палитры.

**Альтернатива:** нормализация `event.key` через раскладочные таблицы —
отклонена: хрупко и требует поддержки карт раскладок, `event.code` решает
проблему нативно.

### D9. Фокус на поле ввода: запрос из палитры и отдельный шорткат

Палитра при переходе в комнату/человека инкрементирует атом-счётчик
`messageInputFocusAtom` (`src/app/state/messageInputFocus.ts`); `RoomView`
отслеживает токен и ставит фокус через `ReactEditor.focus(editor)` после
`requestAnimationFrame` (композер монтируется в том же рендере). Токен
сравнивается с обработанным, поэтому обычное открытие комнаты мышью фокус
не перехватывает.

Шорткат Ctrl/Cmd+Shift+M матчится по `event.code` (`KeyM`) — работает в любой
раскладке. Обработчик `RoomView` не срабатывает, когда открыто модальное окно
или палитра (`searchModalAtom`), чтобы не перехватывать фокус за модалкой.
Существующее поведение «любая печатная клавиша фокусирует композер»
сохраняется и дополняется проверкой открытых оверлеев.

### D10. Клавиатурное управление и фокус

Переиспользуются `useListFocusIndex` (стрелки/Enter) и FocusTrap; Esc закрывает
палитру (существующее поведение модалки). Открытие по `mod+k` остаётся в
`SearchModalRenderer` с проверкой отсутствия других открытых порталов.
Все строки интерфейса — через i18next (`public/locales/{en,ru,de}.json`).

## Risks / Trade-offs

- **[Рост сложности Search.tsx]** — модалка становится палитрой и разрастается →
  Митигация: вынос провайдеров и реестра команд в отдельные модули
  (`features/search/palette/` или рядом), `Search.tsx` остаётся тонкой
  композицией.
- **[Производительность при большом числе комнат]** — fuzzy-матчинг по всем
  комнатам/пользователям на каждый ввод → Митигация: существующий батчинг
  `useAsyncSearch`, лимит результатов на категорию (top-N), отмена устаревших
  вычислений.
- **[Смешение категорий в одном списке]** — команда может затеряться среди
  комнат → Митигация: группировка с заголовками категорий, фиксированный
  порядок (действия при точном совпадении выше), префикс `>` для режима
  «только команды» (опционально, фиксируется при реализации).
- **[Расхождение с upstream Cinny]** — форк сильнее отойдёт от upstream →
  Принимается осознанно: палитра — осознанное отличие Harrier (см. proposal).
- **[Невалидные элементы истории]** — комната покинута, пресет удалён →
  Митигация: фильтрация при рендере, повторное сохранение очищенной истории.

## Migration Plan

Миграции данных не требуется. Палитра — аддитивная функция; существующее
поведение поиска комнат сохраняется (те же префиксы `#`/`@`/`*`). Откат —
revert коммита в форке, десктоп-обёртка не затрагивается.

## Open Questions

- Префикс `>` для режима «только команды» — ввести сразу или отложить?
  (По умолчанию: не вводить, команды матчатся в общем потоке; решение
  зафиксировать при реализации по ощущениям от UX.)
- Серверный поиск пользователей (`/user_directory/search`) — добавлять ли
  отдельным провайдером позже (за рамками этого change).
