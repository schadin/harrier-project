# Delta Spec: command-palette (новая возможность)

## ADDED Requirements

### Requirement: Открытие и закрытие палитры

Система SHALL предоставлять Command Palette — модальное окно поиска и команд,
открываемое по Ctrl/Cmd+P из любого экрана приложения. Палитра SHALL
закрываться по Esc и SHALL быть полностью управляемой с клавиатуры
(навигация стрелками, выполнение по Enter). Палитра не открывается, если
уже открыто другое модальное окно (портал).

#### Scenario: Открытие палитры горячей клавишей

- **WHEN** пользователь нажимает Ctrl+P (Cmd+P на macOS) на любом экране
  приложения без открытых модальных окон
- **THEN** открывается Command Palette с фокусом в поле ввода

#### Scenario: Закрытие по Esc

- **WHEN** палитра открыта и пользователь нажимает Esc
- **THEN** палитра закрывается, фокус возвращается в приложение

#### Scenario: Не открывать поверх другой модалки

- **WHEN** открыто другое модальное окно и пользователь нажимает Ctrl/Cmd+P
- **THEN** палитра не открывается

### Requirement: Шорткаты, независимые от раскладки

Шорткаты палитры SHALL срабатывать независимо от текущей раскладки клавиатуры
и языка ввода. Матчинг горячих клавиш SHALL выполняться по физической клавише
(`event.code`), а не по символу (`event.key`).

#### Scenario: Открытие палитры в кириллической раскладке

- **WHEN** активна русская раскладка клавиатуры и пользователь нажимает
  Ctrl+P (физическая клавиша P, которая в этой раскладке даёт «з»)
- **THEN** Command Palette открывается так же, как в латинской раскладке

### Requirement: Переход к комнатам, пространствам и лобби

Система SHALL искать по комнатам (название, алиас, room ID) и пространствам
(включая лобби пространств) и при выборе результата выполнять переход через
существующую навигацию (`useRoomNavigate`: `navigateRoom`/`navigateSpace`).

#### Scenario: Переход к комнате по названию

- **WHEN** пользователь вводит часть названия комнаты и нажимает Enter на
  результате категории «Комнаты»
- **THEN** палитра закрывается и приложение переходит в выбранную комнату

#### Scenario: Переход к пространству

- **WHEN** пользователь выбирает пространство или лобби в результатах
- **THEN** приложение переходит в выбранное пространство

### Requirement: Переход к пользователям

Система SHALL искать пользователей по имени и MXID среди членов известных
комнат (в первую очередь DM). При выборе пользователя, с которым есть
DM-комната, система SHALL перейти в неё; иначе — открыть создание чата с
предзаполненным получателем.

#### Scenario: Открытие существующего DM

- **WHEN** пользователь выбирает человека, с которым существует DM-комната
- **THEN** приложение переходит в эту комнату

#### Scenario: Создание нового DM

- **WHEN** пользователь выбирает человека, с которым нет DM-комнаты
- **THEN** открывается экран создания чата с предзаполненным MXID получателя

### Requirement: Переход к разделам настроек

Система SHALL включать в результаты разделы настроек (General, Account,
Status, Notifications, Devices, Emojis & Stickers, Developer Tools, About)
с локализованными названиями и при выборе открывать соответствующий раздел
через `useOpenSettingsPage`.

#### Scenario: Открытие раздела настроек

- **WHEN** пользователь выбирает раздел «Уведомления» в результатах палитры
- **THEN** палитра закрывается и открывается модалка настроек на разделе
  уведомлений

### Requirement: Выполнение команд

Система SHALL предоставлять команды: смена статуса по пресету, mute/unmute
текущей комнаты, «отметить всё прочитанным», logout, создание комнаты,
создания DM, создания пространства. Команды SHALL выполняться через
существующие механизмы клиента (presence, настройки уведомлений комнаты,
read receipts, logout, модалки создания). Асинхронные команды SHALL
отображать индикатор выполнения и закрывать палитру по завершении.

#### Scenario: Смена статуса из палитры

- **WHEN** пользователь выбирает команду смены статуса и пресет
- **THEN** статус публикуется через Matrix presence (существующий механизм
  `setCustomStatus`), палитра закрывается

#### Scenario: Отметить всё прочитанным

- **WHEN** пользователь выбирает команду «Отметить всё прочитанным»
- **THEN** команда выполняется с индикатором загрузки, по завершении палитра
  закрывается, непрочитанные маркеры сбрасываются

#### Scenario: Mute текущей комнаты

- **WHEN** пользователь находится в комнате и выбирает команду mute
- **THEN** настройки уведомлений текущей комнаты переключаются через
  существующий механизм `setRoomNotificationPreference`

### Requirement: Быстрое создание комнаты, DM и пространства

Система SHALL предоставлять команды создания комнаты, DM и пространства,
открывающие существующие модалки/экраны создания (`useOpenCreateRoomModal`,
`CreateChat`, `CreateSpaceModal`).

#### Scenario: Создание комнаты из палитры

- **WHEN** пользователь выбирает команду «Создать комнату»
- **THEN** палитра закрывается и открывается модалка создания комнаты

### Requirement: Fuzzy-поиск с подсветкой и группировкой

Система SHALL выполнять fuzzy-поиск (subsequence-матчинг с ранжированием:
точное совпадение > префикс > подстрока > subsequence) и подсвечивать
совпавшие символы в результатах. Результаты SHALL группироваться по
категориям с заголовками: комнаты, люди, пространства, настройки, действия.
Существующие префиксы поиска (`#`, `@`, `*`) SHALL сохранить своё поведение.

#### Scenario: Fuzzy-совпадение

- **WHEN** пользователь вводит «gnr»
- **THEN** в результатах появляется комната «General» с подсвеченными
  символами g, n, r

#### Scenario: Группировка результатов

- **WHEN** запрос совпадает с комнатой, пользователем и командой
- **THEN** результаты отображаются группами с заголовками категорий

### Requirement: История последних действий

Система SHALL сохранять последние 10 выполненных элементов палитры локально
(localStorage) и показывать их при пустом запросе. Невалидные элементы
(покинутая комната, удалённый пресет) SHALL молча исключаться.

#### Scenario: История при пустом запросе

- **WHEN** пользователь открывает палитру с пустым запросом и история не пуста
- **THEN** отображаются последние выполненные элементы

#### Scenario: Фильтрация невалидных элементов истории

- **WHEN** элемент истории ссылается на покинутую комнату
- **THEN** элемент не отображается в истории

### Requirement: Фокус на поле ввода сообщения

После перехода в комнату (или DM) из Command Palette система SHALL ставить
фокус в поле ввода сообщения. Система SHALL также предоставлять шорткат
Ctrl/Cmd+Shift+M для фокусировки поля ввода из любого места приложения
(матчинг по физической клавише, работает в любой раскладке). Шорткат не
срабатывает, пока открыто модальное окно (в том числе сама палитра).

#### Scenario: Фокус после перехода из палитры

- **WHEN** пользователь выбирает комнату в Command Palette
- **THEN** приложение переходит в комнату и фокус оказывается в поле ввода
  сообщения

#### Scenario: Фокус по горячей клавише

- **WHEN** пользователь нажимает Ctrl/Cmd+Shift+M при открытой комнате и
  отсутствии модальных окон
- **THEN** фокус перемещается в поле ввода сообщения

#### Scenario: Шорткат не мешает открытой палитре

- **WHEN** открыта Command Palette и пользователь нажимает Ctrl/Cmd+Shift+M
- **THEN** фокус в поле ввода не переносится, палитра продолжает работать

### Requirement: Быстрый список непрочитанных чатов

Система SHALL предоставлять команду «Непрочитанные чаты», которая
переключает палитру в режим фильтра по непрочитанным комнатам. Для каждой
комнаты в списке SHALL отображаться первое непрочитанное сообщение
(отправитель и текст/плейсхолдер медиа), счётчик непрочитанных и сортировка
по highlight, затем по количеству непрочитанных. Выход из режима — по
Backspace в пустом поле или выбор команды заново; Esc закрывает палитру.

#### Scenario: Фильтр непрочитанных с превью

- **WHEN** пользователь выбирает команду «Непрочитанные чаты»
- **THEN** палитра показывает только непрочитанные комнаты с превью первого
  непрочитанного сообщения каждой

#### Scenario: Превью показывает входящее сообщение, а не собственное

- **WHEN** после последнего прочитанного события в комнате есть собственные
  сообщения пользователя
- **THEN** превью показывает первое входящее (не своё) непрочитанное
  сообщение; если входящих после receipt нет — превью отсутствует

#### Scenario: Шифрованные комнаты

- **WHEN** первое непрочитанное сообщение в E2E-комнате расшифровано
- **THEN** превью показывает расшифрованный текст; при ошибке расшифровки —
  плейсхолдер «зашифрованное сообщение»

#### Scenario: Нет непрочитанных

- **WHEN** все комнаты прочитаны и выбрана команда «Непрочитанные чаты»
- **THEN** отображается пустое состояние «Нет непрочитанных чатов»

### Requirement: Пустое состояние и i18n

Система SHALL показывать при пустом запросе без истории подсказки (примеры
запросов, шорткаты, префиксы). Все строки палитры SHALL быть локализованы
через i18next (en, ru, de).

#### Scenario: Подсказки в пустом состоянии

- **WHEN** палитра открыта, запрос пуст и история пуста
- **THEN** отображаются подсказки по использованию палитры
