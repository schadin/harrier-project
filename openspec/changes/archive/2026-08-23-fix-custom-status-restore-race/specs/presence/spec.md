# presence Delta

## MODIFIED Requirements

### Requirement: Восстановление статуса после перезапуска
Система SHALL локально сохранять активный статус (`cinny_active_status_msg`) и
восстанавливать его после перезапуска. Решение о восстановлении SHALL
приниматься только при известном серверном значении — после прихода собственного
`m.presence` (`presenceStatusMsg !== undefined`) либо по истечении
страховочного таймаута. Приоритет сервера: непустой серверный статус,
отличающийся от локального, SHALL синхронизировать локальный кэш с серверным без
отправки `setPresence`. Локальный статус восстанавливается на сервере только
если серверное значение пустое; при восстановлении текущее presence
пользователя SHALL сохраняться (без форсирования `online`). Перед
`startClient()` вызывается `mx.setSyncPresence('online')` для корректного
получения presence-событий. Ошибка отправки `setPresence` не блокирует работу.

#### Scenario: Перезапуск приложения
- **WHEN** приложение перезапускается и приходит собственное `m.presence`,
  а сервер не вернул статус (значение пустое)
- **THEN** активный статус восстанавливается из локального хранилища
- **AND** presence пользователя не принудительно меняется на `online`

#### Scenario: Сервер вернул актуальный статус
- **WHEN** после перезапуска приходит собственное `m.presence` с непустым
  статусом, отличающимся от локального кэша
- **THEN** локальный кэш синхронизируется с серверным значением
- **AND** `setPresence` на сервер не отправляется

#### Scenario: Серверный статус совпадает с локальным
- **WHEN** приходит собственное `m.presence` со значением, равным локальному
- **THEN** никаких отправок и изменений кэша не выполняется

#### Scenario: Presence не приходит
- **WHEN** собственное `m.presence` не поступило в течение страховочного
  таймаута после SYNCING
- **THEN** решение принимается по состоянию на момент таймаута (как при
  неизвестном значении — восстановление не выполняется)
