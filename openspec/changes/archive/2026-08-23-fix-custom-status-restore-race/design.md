# Design: fix-custom-status-restore-race

## Context

`CustomStatusRestore` запускает `restoreCustomStatus` на первый SYNCING.
В этот момент собственное presence ещё не получено
(`user.presenceStatusMsg === undefined`), guard «сервер имеет приоритет»
не срабатывает, и локальное значение уходит на сервер через `setPresence`,
затирая актуальный статус. Форсирование `presence: 'online'` дополнительно
ломает авто-away.

## Goals / Non-Goals

**Goals**

- Решение о восстановлении — только при известном серверном значении.
- Приоритет сервера: непустой отличный от локального статус → локальный кэш
  обновляется, на сервер ничего не отправляется.
- Без форсирования presence: при восстановлении передаётся текущее presence
  пользователя.

**Non-Goals**

- Переход хранения активного статуса на jotai-атом (рассмотрено, отложено:
  требует рефакторинга UI-потребителей, к решению гонки отношения не имеет).
- Изменение форматов статусов, пресетов, notice-публикации.

## Decisions

1. **Ожидание собственного `UserEvent.Presence`**: решение принимается при
   первом известном `presenceStatusMsg`. Страховочный таймаут (15 c после
   подписки) покрывает сценарий, когда presence-событие не приходит вовсе.
2. **Матрица решений при известном серверном значении**:
   - `serverMsg === saved` → ничего не делать;
   - `serverMsg` непустое и отличается → сервер новее, локальный кэш
     обновляется;
   - `serverMsg` пустое → серверное значение утеряно/истекло, локальный
     статус восстанавливается с текущим presence.
   Альтернатива «всегда приоритет сервера, включая пустое значение» сделала бы
   функцию восстановления мёртвой кодом (после перезапуска restore вырождался
   бы в no-op); компромисс зафиксирован в спеке.
3. **Таймаут в компоненте, логика решения — в плагине**: подписка/таймер —
   React-логика (`CustomStatusRestore`), матрица решений — чистая функция
   `restoreCustomStatus(mx)` (тестируема без React).

## Risks / Trade-offs

- [Статус, снятый с другого устройства, может «воскреснуть», если локальный
  кэш этого устройства устарел] → принимается: обратный риск (потеря статуса
  после перезапуска) считался хуже; кейс редкий, снятие на том же устройстве
  всегда чистит кэш до отправки.
- [Presence-события задерживаются] → таймаут гарантирует применение старого
  поведения как fallback.
