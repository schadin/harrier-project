# Design: fix-backup-restore-retry-loop

## Context

`useRestoreBackupOnStartup` запускает цепочку восстановления на первый SYNCING.
Guard пропускает запуск только при статусах Fetching/Loading/Done; при ошибке
или отсутствии бэкапа статус остаётся `Idle`, поэтому каждая следующая синхронизация
(каждые ~20–30 с) порождает новую попытку — бесконечный цикл. Дополнительно
`restoreProgress.status` в deps колбэка пересоздаёт подписку на каждый тик
прогресса.

## Goals / Non-Goals

**Goals**

- Одна попытка авто-восстановления за сессию (после первого SYNCING) независимо
  от результата.
- Повтор только по значимому событию: `KeyBackupDecryptionKeyCached`.
- Стабильная подписка на sync без пересозданий.

**Non-Goals**

- Изменение ручного восстановления (BackupRestore.tsx) и
  `useRestoreBackupOnVerification`.
- Backoff-политика повторов (достаточно event-driven повтора).
- Переход статуса в `Done` при ошибке (атом отражает UI-прогресс, не признак
  «попытка совершена»).

## Decisions

1. **Локальный ref `attemptedRef` вместо статуса атома**: признак «попытка уже
   была» — логика хука, а не UI-состояние; выставляется в finally после первой
   попытки. Альтернатива (ставить Done в атом при ошибке) искажала бы UI.
2. **Сброс `attemptedRef` в колбэке `useKeyBackupDecryptionKeyCached`**: кэширование
   ключа расшифровки — единственное событие, после которого ранее провальная
   попытка может завершиться успехом. Требование сценария «Восстановление по
   событию появления ключа» сохраняется.
3. **`progressStatusRef` для чтения статуса**: устраняет зависимость
   `restoreProgress.status` из deps колбэка; эффект синхронизирует ref.

## Risks / Trade-offs

- [Провал из-за временной недоступности сервера больше не ретраится автоматически]
  → пользователь может восстановить вручную; при появлении ключа повтор
  произойдёт по `KeyBackupDecryptionKeyCached`; страховка сохранена.
- [Гонка между установкой ref и первым тиком прогресса] → ref выставляется до
  первого await невозможен (нужен результат), поэтому сброс выполняется в
  колбэке события до вызова restoreBackup.
