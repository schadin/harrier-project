# Messaging Specification

## Purpose

Статусы собственных сообщений и маркеры прочтения в ленте комнаты и Direct-чатах,
а также прикрепление файлов и вставка изображений из буфера обмена.

## Requirements

### Requirement: Индикация статуса сообщения в Direct
Система SHALL отображать в личных чатах (Direct) статус собственных сообщений:
`Check` (отправлено — событие доставлено на сервер), `CheckTwice` (прочитано —
read receipt собеседника), `Clock` (отправка), `Cross` (ошибка). «Доставлено» не
реализуется — в протоколе Matrix нет механизма доставки на устройство.

#### Scenario: Сообщение прочитано собеседником
- **WHEN** собственное сообщение в Direct получило read receipt собеседника
- **THEN** рядом со временем отображается `CheckTwice`

### Requirement: Маркеры прочтения (аватары) в ленте
Система SHALL отображать маркеры прочтения как группу круглых аватаров (16px,
перекрытие, лимит 3 + «+N») под сообщением. Receipt со скрытого/системного события
резолвится к ближайшему видимому (один проход вперёд). Режимы:
`roomReadReceipts` / `directReadReceipts` (`avatars` / `status` / `checkmark` / `off`),
дефолт `avatars`.

#### Scenario: Маркеры под сообщением
- **WHEN** режим `roomReadReceipts` равен `avatars` и у сообщения есть читатели
- **THEN** под сообщением отображается группа аватаров читателей
- **AND** клик по группе открывает модалку «Seen by»

#### Scenario: Скрытое сообщение
- **WHEN** read receipt пришёл на скрытое/системное событие
- **THEN** маркер резолвится к ближайшему следующему видимому событию

### Requirement: Прикрепление файла с первого раза
Система SHALL гарантировать, что выбор файла через `<input type="file">`
срабатывает с первого раза: input добавляется в DOM перед `click()`, удаляется
после выбора/отмены, обрабатывается `cancel` и фолбэк по `window.focus`.

#### Scenario: Выбор файла
- **WHEN** пользователь выбирает файл в диалоге
- **THEN** файл прикрепляется с первой попытки без двойного клика

### Requirement: Вставка изображения из буфера обмена
Система SHALL вставлять изображение из буфера обмена в чат. При пустом
`clipboardData.files` (в Tauri) изображение читается через `readImage` и
конвертируется RGBA → PNG.

#### Scenario: Вставка изображения
- **WHEN** пользователь вставляет изображение из буфера обмена
- **THEN** изображение прикрепляется как PNG-файл

### Requirement: Причина неудачной расшифровки в ленте
Система SHALL отображать вместо общей заглушки «Unable to decrypt message»
локализованное сообщение о причине неудачной расшифровки, определённой по
`MatrixEvent.decryptionFailureReason` (`DecryptionFailureCode`). Если причина
отсутствует или неизвестна (`null` / `UNKNOWN_ERROR`), система SHALL показывать
общий текст о невозможности расшифровать сообщение.

#### Scenario: Ключ сессии ещё не получен
- **WHEN** событие не расшифровано с причиной `MEGOLM_UNKNOWN_INBOUND_SESSION_ID`
- **THEN** отображается текст «Ключ для сообщения ещё не получен»
- **AND** сообщение остаётся в состоянии ожидания ключа

#### Scenario: Ключ удержан из-за неверифицированного устройства
- **WHEN** событие не расшифровано с причиной `MEGOLM_KEY_WITHHELD_FOR_UNVERIFIED_DEVICE`
- **THEN** отображается текст «Отправитель не выдаёт ключ: устройство не верифицировано»

#### Scenario: Историческое сообщение без доступа к бэкапу
- **WHEN** событие не расшифровано с причиной `HISTORICAL_MESSAGE_NO_KEY_BACKUP`
  или `HISTORICAL_MESSAGE_BACKUP_UNCONFIGURED`
- **THEN** отображается текст «Историческое сообщение, ключ недоступен — требуется
  настроить или восстановить бэкап ключей»

#### Scenario: Неизвестная причина
- **WHEN** событие не расшифровано, а `decryptionFailureReason` равен `null`
  или `UNKNOWN_ERROR`
- **THEN** отображается общий текст о невозможности расшифровать сообщение

### Requirement: Действие по причине неудачной расшифровки
Система SHALL предлагать пользователю контекстное действие (CTA) в зависимости
от причины неудачной расшифровки: «Запросить ключ» для причин, когда ключ может
быть получен позже; «Верифицировать устройство» для
`MEGOLM_KEY_WITHHELD_FOR_UNVERIFIED_DEVICE`; «Настроить/восстановить бэкап» —
для исторических причин вида `HISTORICAL_MESSAGE_*`. Для причин, не имеющих
эффективного действия, CTA SHALL отсутствовать.

#### Scenario: Запрос ключа для ожидаемого ключа
- **WHEN** событие не расшифровано с причиной `MEGOLM_UNKNOWN_INBOUND_SESSION_ID`
- **THEN** рядом с причиной отображается действие «Запросить ключ»

#### Scenario: Переход к верификации устройства
- **WHEN** событие не расшифровано с причиной `MEGOLM_KEY_WITHHELD_FOR_UNVERIFIED_DEVICE`
- **THEN** отображается действие «Верифицировать устройство»
- **AND** действие открывает настройки устройств

#### Scenario: Переход к бэкапу ключей
- **WHEN** событие не расшифровано с причиной `HISTORICAL_MESSAGE_NO_KEY_BACKUP`
  или `HISTORICAL_MESSAGE_BACKUP_UNCONFIGURED`
- **THEN** отображается действие «Настроить/восстановить бэкап»
- **AND** действие открывает панель резервного копирования

#### Scenario: Нет действия для необратимой причины
- **WHEN** событие не расшифровано с причиной без эффективного действия
  (например, `SENDER_IDENTITY_PREVIOUSLY_VERIFIED`)
- **THEN** отображается только причина без CTA

### Requirement: Снятие бейджа непрочитанного после прочтения
Система SHALL снимать бейдж непрочитанного с комнаты сразу после её прочтения в
текущей сессии, без перезапуска приложения. Атом непрочитанного SHALL
пересчитываться при изменении счётчика непрочитанного в matrix-js-sdk, а
повторное добавление комнаты как непрочитанной по устаревшему серверному счётчику
SHALL быть исключено.

#### Scenario: Прочтение комнаты в текущей сессии
- **WHEN** пользователь открывает комнату с непрочитанными сообщениями и читает её (находится внизу ленты, окно в фокусе)
- **THEN** бейдж непрочитанного в списке комнат и в трее снимается сразу
- **AND** последующее живое событие (новое сообщение, правка, реакция) не возвращает устаревший счётчик, если комната уже прочитана

#### Scenario: Обнуление счётчика на сервере
- **WHEN** сервер в sync сообщает `notification_count: 0` для прочитанной комнаты
- **THEN** атом непрочитанного пересчитывается и комната удаляется из непрочитанных

#### Scenario: Новое сообщение после прочтения
- **WHEN** после прочтения комнаты приходит новое сообщение
- **THEN** комната снова помечается непрочитанной с актуальным счётчиком
