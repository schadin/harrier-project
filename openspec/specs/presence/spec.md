# Presence Specification

## Purpose

Управление пользовательским присутствием и кастомным статусом в протоколе Matrix:
онлайн-статус, время последней активности, кастомный статус (emoji + текст),
пресеты, восстановление после перезапуска и уведомление комнаты о смене статуса.

## Terms

- **Кастомный статус** — пара emoji + текст, закодированная в поле `status_msg`
  presence пользователя (`{emoji} {text}[ · HH:MM]`); emoji — первый графем
  (`\p{Extended_Pictographic}`, разбор через `Intl.Segmenter`).
- **Пресет статуса** — сохранённая пара emoji + текст; стандартные пресеты:
  🟢 «На месте», 🙅‍♂️ «Отошел», 🍴 «Обед», 🏁 «Ушел»; пользовательские хранятся в
  настройке `statusPresets`.
- **Активный статус** — статус, сохранённый локально под ключом
  `cinny_active_status_msg` для восстановления после перезапуска.
- **Метка присутствия** — текстовое представление presence: online → «Active»,
  unavailable → «Busy», offline → «Away».
## Requirements
### Requirement: Кастомный статус через Matrix presence
Система SHALL позволять пользователю устанавливать кастомный статус (emoji + текст)
через поле `status_msg` протокола Matrix presence. Значение optimistically
обновляется синхронно до HTTP-запроса (локальный `User.presenceStatusMsg` + ручной
эмит `UserEvent.Presence`). Текст статуса ограничен 60 символами; к статусу может
добавляться суффикс времени установки « · HH:MM», не влияющий на сравнение статусов.

#### Scenario: Установка статуса
- **WHEN** пользователь вводит emoji и текст в редакторе статуса и подтверждает
- **THEN** статус публикуется через `presence.status_msg` и сразу отображается
- **AND** карточка пользователя показывает emoji + текст статуса серым

#### Scenario: Очистка статуса
- **WHEN** пользователь очищает статус
- **THEN** `status_msg` сбрасывается и статус удаляется из карточек

### Requirement: Быстрая смена статуса
Система SHALL предоставлять кнопку профиля с emoji активного статуса и
PopOut-меню пресетов для быстрой смены. Активный пресет отмечается галочкой;
сравнение выполняется без учёта суффикса времени.

#### Scenario: Быстрая смена из меню кнопки профиля
- **WHEN** пользователь открывает меню кнопки профиля и выбирает пресет
- **THEN** статус немедленно меняется на выбранный пресет

### Requirement: Пресеты статуса
Система SHALL поддерживать стандартные пресеты (`DEFAULT_STATUS_PRESETS`) и
кастомные пресеты (настройка `statusPresets`), объединяемые в меню. Кастомные
пресеты можно редактировать и удалять с двухфазным подтверждением.
Пресет не может быть создан без emoji.

#### Scenario: Редактирование кастомного пресета
- **WHEN** пользователь редактирует emoji/текст пресета
- **THEN** пресет обновляется, а если он активен — статус синхронизируется

#### Scenario: Удаление кастомного пресета
- **WHEN** пользователь удаляет пресет с подтверждением
- **THEN** пресет удаляется, а если он был активен — статус очищается

### Requirement: Стандартный статус присутствия и время последней активности
Система SHALL отображать онлайн-статус (цветной кружок + метка) и время
последней активности пользователя в карточках, DM-шапке, элементах списка
комнат direct-чатов и списке участников. Метка времени формируется относительно
текущего момента («Was online N min ago», «Last seen yesterday at HH:mm» и т.д.).

#### Scenario: Отображение присутствия
- **WHEN** presence-событие пользователя получено
- **THEN** под именем отображается метка статуса с тултипом времени последней активности

### Requirement: Восстановление статуса после перезапуска
Система SHALL локально сохранять активный статус (`cinny_active_status_msg`) и
восстанавливать его после перезапуска. Решение о восстановлении SHALL
приниматься только при известном серверном значении — после прихода собственного
`m.presence` (`presenceStatusMsg !== undefined`) либо по истечении
страховочного таймаута. Приоритет сервера: непустой серверный статус,
отличающийся от локального, SHALL синхронизировать локальный кэш с серверным без
отправки `setPresence`. Локальный статус восстанавливается на сервере только
если серверное значение пустое; при восстановлении текущее presence
пользователя SHALL сохраняться (без форсирования `online`). Перед
`startClient()` вызывается `mx.setSyncPresence('online')` для корректного
получения presence-событий. Ошибка отправки `setPresence` не блокирует работу.

#### Scenario: Перезапуск приложения
- **WHEN** приложение перезапускается и приходит собственное `m.presence`,
  а сервер не вернул статус (значение пустое)
- **THEN** активный статус восстанавливается из локального хранилища
- **AND** presence пользователя не принудительно меняется на `online`

#### Scenario: Сервер вернул актуальный статус
- **WHEN** после перезапуска приходит собственное `m.presence` с непустым
  статусом, отличающимся от локального кэша
- **THEN** локальный кэш синхронизируется с серверным значением
- **AND** `setPresence` на сервер не отправляется

#### Scenario: Серверный статус совпадает с локальным
- **WHEN** приходит собственное `m.presence` со значением, равным локальному
- **THEN** никаких отправок и изменений кэша не выполняется

#### Scenario: Presence не приходит
- **WHEN** собственное `m.presence` не поступило в течение страховочного
  таймаута после SYNCING
- **THEN** решение принимается по состоянию на момент таймаута (как при
  неизвестном значении — восстановление не выполняется)

### Requirement: Уведомление комнаты о смене статуса
Система SHALL отправлять `m.notice` с текстом статуса в указанную комнату
(настройка `statusNoticeRoomId`) при установке статуса. Сообщение SHALL НЕ
отправляться: при пустой комнате, при снятии статуса и при автовосстановлении
после перезапуска. Ошибки отправки игнорируются. Статус, выбранный из меню трея,
публикуется по тем же правилам (включая m.notice).

#### Scenario: Смена статуса с настроенной комнатой
- **WHEN** пользователь устанавливает статус и `statusNoticeRoomId` задан
- **THEN** в указанную комнату отправляется `m.notice` с текстом статуса

#### Scenario: Условия не-отправки
- **WHEN** комната не задана, статус снимается или восстанавливается автоматически
- **THEN** `m.notice` не отправляется
