# Desktop Integration Specification

## Purpose

Нативная интеграция с десктоп-окружением: системный трей, скрытие заголовка окна
под Niri, миграция настроек из Cinny в Harrier при первом запуске и режимы
раздачи фронтенда.

## Terms

- **Трей-иконка** — иконка в системном трее; рендерится фронтендом на canvas
  (база + emoji статуса шрифтом Twemoji + бейдж) и передаётся в Rust как PNG
  через команду `set_tray_icon`.
- **Бейдж трея** — счётчик непрочитанных на иконке: красный `#ff4d4f` при
  highlight > 0, иначе синий `#1890ff`; значение ограничено «99+» (cap 99);
  space-комнаты исключаются.
- **Миграция** — однократное копирование настроек между идентификаторами
  `in.cinny.app` → `io.github.schadin.harrier`.
## Requirements
### Requirement: Системный трей
Система SHALL предоставлять иконку в системном трее со сменой статуса и бейджем
непрочитанных сообщений. Меню: Open → статусы-галочки → Quit. Показ определяется
настройкой `showTrayIcon` (дефолт `false`, переключатель виден только под Tauri):
при включении трей создаётся, при выключении — удаляется. Левый клик по иконке
открывает главное окно (на Linux требует libayatana-appindicator ≥ 0.6.0, при
отсутствии — warning в лог). Выбор пресета в меню эмитит событие
`tray-set-status` во фронтенд. Фоновое поведение (`startMinimized`,
`minimizeOnClose`, перехват `CloseRequested`) не переносится — закрытие окна
завершает приложение.

#### Scenario: Включение трея
- **WHEN** пользователь включает «Show Tray Icon» в настройках Desktop
- **THEN** в трее появляется иконка Harrier с меню статусов

#### Scenario: Смена статуса из трея
- **WHEN** пользователь выбирает статус в меню трея
- **THEN** статус устанавливается (как из UI, включая m.notice), иконка обновляется

#### Scenario: Бейдж непрочитанных
- **WHEN** есть непрочитанные сообщения
- **THEN** на иконке трея отображается бейдж с количеством (без space-комнат,
  без двойного счёта)

### Requirement: Иконка трея — Harrier вместо Cinny
Система SHALL при сборке подставлять в трей Harrier-птицу вместо Cinny. Базовая
иконка `assets/tray-base.png` перезаписывает `public/icons/tray-base.png` через
`rebrand:apply`, revert восстанавливает upstream из git подмодуля. Ошибка рендера
иконки логируется и не приводит к падению приложения.

#### Scenario: Сборка с брендингом
- **WHEN** выполняется ребрендинг при сборке
- **THEN** трей-иконка использует Harrier-птицу

### Requirement: Скрытие заголовка окна под Niri
Система SHALL при наличии переменной окружения `NIRI_SOCKET` отключать
decorations/shadow окна и скрывать GTK-titlebar (`set_titlebar(None)` +
`set_decorated(false)`); окно показывается после применения правок. На macOS
применяется прозрачный titlebar (`TitleBarStyle::Transparent`). Внешние ссылки
из веб-просмотра открываются системным открывателем, встроенная навигация запрещена.

#### Scenario: Запуск под Niri
- **WHEN** приложение запускается при установленном `NIRI_SOCKET`
- **THEN** у окна нет GTK-заголовка

### Requirement: Миграция настроек Cinny → Harrier
Система SHALL при первом старте копировать (не перемещать) настройки
`in.cinny.app` → `io.github.schadin.harrier` (config + data каталоги; Linux —
XDG, macOS/Windows — Application Support / APPDATA), создавать маркер
`migration.success`. Копирование идемпотентно (маркер — выход), never-overwrite
(существующие файлы не перезатираются), не выполняется, если новые каталоги уже
непустые; ошибки отдельных файлов не прерывают миграцию, критические ошибки
не валят приложение.

#### Scenario: Первый запуск после Cinny
- **WHEN** Harrier запускается впервые и находит настройки Cinny
- **THEN** настройки копируются в каталог Harrier без удаления исходных
- **AND** создаётся маркер `migration.success`

#### Scenario: Повторный запуск
- **WHEN** маркер `migration.success` существует
- **THEN** миграция пропускается

### Requirement: Режимы раздачи фронтенда
Система SHALL раздавать статику релизной сборки через tauri-plugin-localhost на
порту 44548 (окно грузит `http://localhost:44548`), а в dev-режиме использовать
Vite HMR на порту 8080. Перед стартом `localhost,127.0.0.1` добавляются в
`NO_PROXY`/`no_proxy`, чтобы прокси не перехватил локальную раздачу. Позиция и
размер окна сохраняются через tauri-plugin-window-state.

#### Scenario: Релизный запуск
- **WHEN** собранное приложение стартует
- **THEN** фронтенд загружается с локального сервера порта 44548

### Requirement: Автозапуск при входе в систему
Система SHALL предоставлять настройку `autostart` (по умолчанию `false`,
переключатель виден только под Tauri) в секции Desktop настроек: при включении
приложение регистрирует автозапуск в операционной системе (Windows — Startup,
Linux — XDG autostart, macOS — LaunchAgent), при выключении — снимает
регистрацию. Регистрация выполняется без аргументов командной строки: запуск
автозапуска обрабатывается как обычный старт приложения. Если операция
завершилась ошибкой, настройка SHALL вернуться в выключенное положение, а
причина SHALL логироваться. Значение настройки хранится в общих настройках
клиента.

#### Scenario: Включение автозапуска
- **WHEN** пользователь включает «Launch at login» в настройках Desktop
- **THEN** Harrier регистрируется в автозапуске операционной системы, и
  переключатель остаётся включённым

#### Scenario: Выключение автозапуска
- **WHEN** пользователь выключает переключатель
- **THEN** регистрация автозапуска снимается

#### Scenario: Ошибка регистрации
- **WHEN** регистрация автозапуска завершается ошибкой
- **THEN** переключатель возвращается в выключенное положение, причина
  логируется

#### Scenario: Переключатель вне десктопной сборки
- **WHEN** приложение запущено в веб-версии
- **THEN** секция Desktop с переключателем автозапуска не отображается, а сама
  настройка не влияет на работу клиента

### Requirement: Один экземпляр приложения
Система SHALL предоставлять в настройках приложения переключатель «Single
instance», доступный только в десктопной версии и имеющий значение по
умолчанию `выключено`.

Если переключатель включён, повторный запуск Harrier SHALL приводить к тому, что
уже запущенный экземпляр перехватывает запуск и активирует своё главное окно —
снимает сворачивание, показывает окно и передаёт ему фокус (тем же способом, что
и показ из трея); второй процесс и второе окно не создаются.

Если переключатель выключен, каждыйый запуск SHALL создавать отдельный экземпляр
приложения со своим процессом и своим окном.

Значение переключателя SHALL сохраняться и учитываться при последующих запусках
приложения. Требование распространяется на Windows, Linux и macOS; веб-версия не
затрагивается.

#### Scenario: Значение по умолчанию
- **WHEN** пользователь ни разу не менял переключатель «Single instance»
- **THEN** переключатель находится в положении `выключено`

#### Scenario: Включённый переключатель, повторный запуск
- **WHEN** переключатель «Single instance» включён и пользователь запускает
  Harrier, когда приложение уже запущено
- **THEN** новое окно не создаётся, а существующее окно показывается и
  получает фокус

#### Scenario: Включённый переключатель, свёрнутое или скрытое окно
- **WHEN** переключатель «Single instance» включён, главное окно запущенного
  экземпляра свёрнуто или скрыто (например, закрыто через трей), и пользователь
  запускает Harrier снова
- **THEN** окно разворачивается, показывается и получает фокус

#### Scenario: Включённый переключатель, первый запуск
- **WHEN** переключатель «Single instance» включён и приложение ещё не запущено
- **THEN** перехвата не происходит и создаётся единственное главное окно

#### Scenario: Выключенный переключатель, повторный запуск
- **WHEN** переключатель «Single instance» выключен и пользователь запускает
  Harrier, когда приложение уже запущено
- **THEN** создаётся отдельный экземпляр приложения со своим окном, ранее
  запущенный экземпляр продолжает работать

#### Scenario: Изменение переключателя при работающем приложении
- **WHEN** пользователь переключает «Single instance» в уже запущенном
  приложении
- **THEN** текущий экземпляр продолжает работать без перезапуска, а новое
  значение применяется при следующем запуске
