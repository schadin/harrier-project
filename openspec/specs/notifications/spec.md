# Notifications Specification

## Purpose

Системные уведомления о новых сообщениях: доставка через Tauri-плагин или
Web Notification API, превью текста сообщения, корректная работа в зашифрованных
комнатах, уведомления о приглашениях.

## Terms

- **Превью сообщения** — текст body уведомления, формируемый `extractMessagePreview`.
- **Highlight** — непрочитанное событие с упоминанием/уведомлением пользователя.
- **Tauri-ветка / Web-ветка** — способ отправки уведомления: плагин
  `tauri-plugin-notification` в десктопе либо Web Notification API в браузере;
  окружение определяется по наличию `__TAURI_INTERNALS__`.

## Requirements

### Requirement: Системные уведомления в Tauri
Система SHALL отправлять системные уведомления через `tauri-plugin-notification`,
с фолбэком на Web Notification API (защищён `try/catch`). Отправка идёт по флагу
`showNotifications` (дефолт `true`) при активной синхронизации (`SYNCING`) только
для live-событий от других пользователей в комнатах с режимом уведомлений ≠ Mute.
Уведомление не показывается, если окно в фокусе и комната открыта. Уведомления
помечаются `tag = roomId`: новое сообщение из комнаты заменяет предыдущее
уведомление этой комнаты; одновременно отображается одно последнее уведомление.
Клик по уведомлению в Tauri desktop-плагине не отдаётся — `onClick` работает
только в браузере (переход к списку уведомлений).

#### Scenario: Новое сообщение
- **WHEN** поступает новое сообщение и уведомления включены
- **THEN** показывается системное уведомление

#### Scenario: Повторные сообщения без роста unread
- **WHEN** приходит событие, не увеличивающее счётчик непрочитанных
  (например, правка или реакция)
- **THEN** повторное уведомление не показывается (дедупликация по unread)

#### Scenario: Запрос разрешения
- **WHEN** пользователь нажимает Enable в настройках уведомлений
- **THEN** разрешение запрашивается через Tauri-плагин; переключатель недоступен,
  пока разрешение не выдано на уровне системы/браузера

### Requirement: Превью текста сообщения
Система SHALL формировать превью текста уведомления через `extractMessagePreview`:
текст обрезается до 100 символов + «…»; для медиа — тип (`Sent an image` и т.д.);
для удалённых — `Message deleted`; для emote — `* body`; для зашифрованных —
`Sent an encrypted message`. Body уведомления: `{username}: {messagePreview}`,
title — имя комнаты, иконка — аватар отправителя/комнаты.

#### Scenario: Текстовое сообщение
- **WHEN** приходит текстовое сообщение
- **THEN** body уведомления содержит `username: <превью текста>`

#### Scenario: Медиа-сообщение
- **WHEN** приходит изображение/видео/аудио/файл
- **THEN** body содержит тип сообщения, например `Sent an image`

### Requirement: Уведомления для зашифрованных комнат
Система SHALL отправлять уведомление для зашифрованных событий после
`MatrixEventEvent.Decrypted` (со страховочным таймером 5 с), а не сразу по
`RoomEvent.Timeline`. Флаг отправленности исключает двойную отправку. Звук
воспроизводится сразу, независимо от результата расшифровки. Текст
`m.bad.encrypted` — `Unable to decrypt message`.

#### Scenario: Зашифрованное сообщение расшифровано
- **WHEN** зашифрованное событие успешно расшифровано
- **THEN** уведомление отправляется с реальным текстом превью

#### Scenario: Расшифровка не успела
- **WHEN** событие не расшифровано за 5 секунд
- **THEN** отправляется уведомление с текстом `Unable to decrypt message`

### Requirement: Уведомления о приглашениях
Система SHALL уведомлять о новых приглашениях в комнаты при росте их количества
(сравнение с предыдущим значением при активной синхронизации). Body —
`You have N new invitation request.`; клик работает только в браузере.

#### Scenario: Новое приглашение
- **WHEN** пользователь получает приглашение при неактивном окне
- **THEN** показывается системное уведомление о приглашении
